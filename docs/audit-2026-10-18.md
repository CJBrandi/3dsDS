# Connection and application bug audit — 2026-10-18

Audited the C application, protocol encoder/decoder, link freshness, safety orchestration, console stream, AC profile/connection handling, NWM scanner, UI/touch routing, config persistence, packaging and release workflow. Findings below distinguish reproducible software defects from behavior that still needs physical hardware. This review cannot establish compatibility with a real 2026 roboRIO or prove the absence of other bugs.

## Fixed findings

| Priority | Finding and consequence | Patch and evidence |
| --- | --- | --- |
| High | The receive loop overwrote status for each queued reply and evaluated safety only afterward. A code-loss or E-stop reply followed by a healthy reply could disappear before safety observed it. | Observe each accepted reply immediately, latch E-stop in session safety, disable on code loss, invalidate pending acknowledgments and end the batch. Native loopback tests send fault/recovery bursts and verify that recovery stays disabled. Latest fault telemetry remains visible. |
| High | The 100 ms stall check ran only at loop entry. Work blocking later in the same iteration could be followed by another enabled send before the next check. Readiness also used the old iteration timestamp. | Refresh time after UI/service work, consume lifecycle events again, discard readiness/enable touches after a stall, and recheck link/code/Wi-Fi-operation state at transmission. Native-function tests cover the 100/101 ms boundary, lifecycle-event invalidation and final send guard. Complete main-loop scheduling and lifecycle callbacks still require hardware validation. |
| Medium | A reply arriving 249 ms after its send could renew readiness for another 250 ms, nearly doubling the age of the acknowledged control exchange. | Bound readiness by the acknowledged send timestamp. Boundary tests cover delayed replies, expiry and clock reversal. This deliberately tightens the existing watchdog policy. |
| Medium | The trace “robot code present” bit was treated as ready even when the status byte reported code initialization. | Require trace `0x20` and clear initializing flag `0x08`. Decoder and socket tests cover initialization with code still present. |
| Medium | Negative axes stopped at −127; WPILib 2026 divides negative raw axes by 128. Full negative travel therefore became −0.9921875. | Scale negative inputs to −128 and positive inputs to +127; use a wide intermediate to avoid integer overflow. Tests cover travel limits, deadzone, clamping and extreme integer inputs. |
| Medium | `recvfrom()` silently truncated status datagrams at 2048 bytes. A valid-looking prefix could pass framing even when the original datagram had an invalid trailer. | Read one extra sentinel byte and reject anything over the bound. A loopback regression uses an otherwise valid 2048-byte prefix with an invalid trailer. |
| Medium | Config saves recorded the selected network's security even if that network had not replaced the saved system profile. Re-selecting a network could also restore the saved-password flag after its password was edited. | Keep saved-profile security separate, update it only after a successful profile save, and retain the edited-password state on repeated selection. Selection/reuse/key-staging tests cover switching away and back and using an edited password. Persist the profile metadata even if association startup subsequently fails. |
| Medium | Reuse of a saved password could bypass supported-security validation. Connection completion could claim success from a matching SSID even when the AC operation or SSID query failed. | Validate detected security before reuse; check all service results. Tests inject status, connect-result and SSID-query failures and unsupported security. |
| Medium | Cancelling while `CloseAsync` was pending immediately marked the operation idle. Another join could overlap it; its late completion could interrupt the new connection. | Keep ownership until the close result or timeout, suppress reconnect after cancellation, and block another join meanwhile. Mock service tests cover cancellation, delayed completion and timeout. |
| Medium | Beacons were not required to be infrastructure APs, and RSN parsing did not validate the optional PMKID tail. Inconsistent privacy/RSN flags could be classified as supported. | Check ESS/IBSS capability bits, require consistent privacy, and bound the entire optional RSN tail. Parser tests cover ad-hoc networks and malformed security metadata. |
| Medium | A stalled scan had no application timeout and indefinitely presented normal scanning feedback. Scan age started at completion even if the call had taken a long time. | Report a ten-second timeout, invalidate/discard its output, and age scans from request start. Retain the worker and enable interlock until the system call returns. Mock service tests verify timeout, late-result rejection and prevention of overlapping workers. |
| Low | Drive could visually offer Enable while Wi-Fi was off or busy, even though the backend refused it. The scan screen's cancel button did not actually cancel scans. | Include Wi-Fi in visual readiness, explain busy/offline states, label and route Cancel scan correctly, and honor busy state for password/show actions. UI assertions and host renders cover these states. |
| Low | SSIDs are byte strings, but labels were passed directly to a UTF-8 font parser. Malformed/non-ASCII bytes could break or truncate labels. | Replace non-ASCII/control bytes with `?` only in labels; preserve original SSID bytes for joining and PBKDF2. A UI test supplies a non-UTF-8 SSID. |
| Low | Rejoining a supported saved secured network unnecessarily reopened the password keyboard. | Reuse saved credentials directly; the password field still explicitly edits them. Selection/reuse tests cover the underlying state. |

## Public protocol cross-check

- The [original FRC networking reverse-engineering research](https://frcnetworking.readthedocs.io/en/latest/driverstation/ds_to_rio.html) supports the standalone UDP ports, version-1 header, 20 ms cadence, Teleop mode, alliance values, joystick/date/timezone tags and network byte order used here. This is public protocol research, not a complete official 2026 conformance specification.
- Its [roboRIO reply research](https://frcnetworking.readthedocs.io/en/latest/driverstation/rio_to_ds.html) identifies the separate trace/code bit, initializing bit, battery fractional byte and extension framing. Those offsets are retained, with initialization now gating readiness.
- [WPILib v2026.2.2 roboRIO HAL](https://github.com/wpilibsuite/allwpilib/blob/v2026.2.2/hal/src/main/native/athena/FRCDriverStation.cpp) explicitly divides negative axes by 128 and nonnegative axes by 127. The normalization fix follows that implementation. HAL delegates the actual wire transport to NI NetComm, so it does not independently prove every packet assumption here.
- WPILib's [RioConsole connection](https://github.com/wpilibsuite/vscode-wpilib/blob/6f10e0331d47551e68f6fb469b601eb4638323d6/vscode-wpilib/src/riolog/rioconsole.ts) uses robot TCP **1741**; its [message decoder](https://github.com/wpilibsuite/vscode-wpilib/blob/6f10e0331d47551e68f6fb469b601eb4638323d6/vscode-wpilib/src/riolog/shared/message.ts) confirms Feed's print/error offsets and length-prefixed detail/location/stack fields. The existing port and decoder were correct. TCP 1740 is the DS control/metadata connection; a dashboard port with the same number 1741 does not invalidate the robot console listener.
- The existing big-endian button mask agrees with [LibDS's FRC implementation](https://github.com/FRC-Utilities/LibDS/blob/master/src/protocols/frc_2020.c). Conflicting behavior in another third-party driver station was not treated as sufficient evidence to change it.
- [devkitPro libctru AC code](https://github.com/devkitPro/libctru/blob/master/libctru/source/services/ac.c), [AC IPC research](https://www.3dbrew.org/wiki/AC_Services), and [NWM scan request/layout research](https://www.3dbrew.org/wiki/NWM_Services) were checked against this app. The existing disconnect IPC header is correct; no header change was made. Tests now assert its exact format. Profile writes and scan results still need real system-service testing.
- [Linux's IEEE 802.11 definitions](https://github.com/torvalds/linux/blob/master/include/linux/ieee80211.h) identify ESS, IBSS and privacy capability bits used to reject incompatible beacons.

## Remaining limitations and validation work

1. **Physical compatibility is still unverified.** Test a secured robot with wheels raised: New 3DS XL launch/rendering, all inputs, actual WPA2 association/profile replacement, scanning, native keyboards, Feed prints/errors/stacks, disabled startup, Enable/Disable, HOME/lid/link/code-loss recovery and real 2026 roboRIO traffic. Linux loopback and mocked service tests do not establish these behaviors.
2. **A hung system-service call cannot safely be killed.** Scan timeout/cancel now invalidates output and reports timeout, but a worker stuck inside synchronous NWM IPC continues to block enable and another scan until it returns. A pending AC close also has no documented cancel command; the app waits for its result or its five-second deadline. Real service cancellation/late-completion behavior remains a hardware test item.
3. **The 100 ms stall threshold is a detector, not a real-time guarantee.** If the process is blocked/suspended, it cannot transmit a disable packet until it runs again. The robot's communication watchdog remains the fallback. The patch prevents renewing enable after the detected stall.
4. **The protocol has no cryptographic authentication.** IP/framing/sequence/time checks reject accidental/stale traffic but cannot authenticate a sender that can spoof the robot on the same network. No incompatible authentication scheme was added to the roboRIO protocol.
5. **Descriptor-dependent robot code remains outside the implemented scope.** UDP Joystick/GenericHID values are supplied; Xbox identity, joystick name/type/axis metadata, FMS, dashboard/NetworkTables, deployment/reboot and match timing remain unsupported. No metadata transport was added based solely on speculation about hardware behavior.
6. **Console and clock behavior need bench evidence.** A silent half-open TCP connection depends on the native network stack eventually reporting an error; normal quiet output cannot by itself prove failure. The console's clock is sent as UTC as documented. Native font rendering and the console byte-to-text policy still need inspection.
7. **Published v0.3.1 remains unchanged.** The patched CIA is a development build using existing version metadata. No release tag or new GitHub release is created by this audit; an already installed release will not acquire these source fixes automatically.

## Validation performed

- `make test`: all seven suites pass with AddressSanitizer and UndefinedBehaviorSanitizer, including the new actual native-function loopback transport suite.
- Cached devkitPro SDK native `make -j2 release`: compilation, linking, CIA packaging and artifact checks pass, preserving the assigned title ID, service permissions, notices and checksums.
- GCC `-fanalyzer` pass over portable protocol/link/safety/feed/Wi-Fi parsing/settings and mocked native Wi-Fi modules: no diagnostics. This is a supplemental static check, not exhaustive verification.
- `python3 tools/render_previews.py`: regenerated the standard host layout renders. Visually inspected the overview and additional actual-UI renders for Wi-Fi off, Wi-Fi busy and scan timeout. Standard preview assets are unchanged by these state-only UI changes.
- No physical console or roboRIO testing was performed.
